# Failure-informed JSON-lifecycle exploratory successor, v1

This protocol is a versioned successor to the immutable confirmatory 0/48
acquisition NO-GO and the immutable stopped native-tool lifecycle run. It is
exploratory, failure-informed, and exact-task-ID-held-out only. It cannot make
confirmatory efficacy, superiority, task-family, template-level, benchmark-wide
generalization, or exact-ReMe-paper-reproduction claims.

The frozen manifest content hash is
`dce75b4e4e51127bd41025df30c1571e47354d2f6948fa82de6f308ba12616c8`.

## Transport split

AppWorld executor actions retain the locked native-tool transport. Lifecycle
generation uses a separate locked OpenRouter text request with the same model,
provider-only, fallback-disabled, non-thinking, non-streaming, and 1,024-token
constraints. Lifecycle requests contain no `tools` or `tool_choice` field.

The whole assistant content must be exactly one JSON object. The parser rejects
leading/trailing text, Markdown, multiple objects, duplicate keys, unknown
fields, missing fields, invalid types, and truncation. Raw-response and
parsed-output hashes, usage, latency, provider/model, and validation are
write-once records. No repair, extraction, retry, regeneration, or offline
fallback is permitted after a malformed response.

Frozen method schemas:

- `copromem_complexity_v1`: exactly `is_compound` (boolean) and `rationale`
  (string).
- `copromem_subgoals_v1`: exactly `subgoals`, a two- or three-element list of
  objects with exactly `description` (nonempty string) and `is_atomic`
  (boolean).
- `reme_failure_reflection_v1`: exactly `failure_evidence_ids` (nonempty
  strings) and `memory_text` (string). The faithful ReMe adaptation has no
  paid lifecycle call in this source-pool state; this schema freezes the same
  parser/failure policy should such a registered call exist.
