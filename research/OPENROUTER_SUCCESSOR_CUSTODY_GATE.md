# OpenRouter successor pilot - task-custody gate

**Decision: blocked before payload access or paid task dispatch.**

The official AppWorld `dev.txt` inventory was read only as a split manifest;
no task payload or `test_normal` payload was opened. It contains 57 IDs.

An exact-ID exposure set was constructed from committed reports, local research
artifacts, manifests, journals, scripts, and saved records. It contains 48
task IDs. After exact-ID exclusion, only **42** IDs remain. The requested
design needs **44 disjoint IDs** (12 acquisition + 32 evaluation), so it
cannot be frozen without reusing an exposed ID.

This is already a failure of the requested clean-new-pool requirement. The
stricter family-level exclusion is smaller again because several unused
variants share a family prefix with prior development tasks; such variants are
not suitable substitutes for a defensible fresh split.

The candidate listing was generated from IDs only and is not a task manifest.
No route, scorer, model, lifecycle, or evaluation call was dispatched.

The separate cost gate does pass for the requested numerical design at USD
33.3596971 under its explicit registered call caps, but budget feasibility
does not cure the custody failure. A custodian-supplied fresh split, or a
revised study with no more than the available clean IDs and explicit approval,
is required before task selection.
