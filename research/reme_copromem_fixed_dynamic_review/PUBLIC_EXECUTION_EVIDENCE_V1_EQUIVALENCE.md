# Native execution-evidence v1 equivalence fixture

This is a zero-model, zero-provider verification using the previously exposed
native AppWorld fixture `82e2fac_1`.  It is not benchmark performance evidence.
No task instruction, API response, action values, task database contents, or
scorer detail is retained in this report.

## Result

The native worker executed two independent clean fixture states: telemetry off
and telemetry on.  The telemetry-on state used an explicit E-backed journal,
completed its startup open/flush/fsync/read-back preflight, and recorded five
response-attested public dispatcher entries for one submitted program.

| Check | Result |
|---|---|
| Public action return digest | Identical |
| Final native-state digest | Identical |
| Official score tuple | Identical |
| Model-visible instruction/tool interface digest | Identical |
| Direct/loop/conditional/helper dispatch order | Five expected entries, exact order |
| Missing or duplicate evidence entries | None |
| Telemetry journal failure | None |
| Provider/model/embedding calls | None |

The first implementation attempt was retained only as a sanitized diagnosis:
the in-dispatch write was blocked by AppWorld's read-only execution guard.  The
current implementation queues redacted call metadata during program execution
and fsyncs it after the guard is restored, before the action acknowledgement.

The machine-readable, ignored local fixture result is generated by
`scripts/verify_native_execution_evidence.py`; this checked-in report contains
only the audit conclusion.
