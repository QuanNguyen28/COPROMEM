# Official AppWorld train-trajectory archive: metadata-only gate

Registered 2026-09-16 before downloading or decoding the output archive. This
is independent, zero-model-call source feasibility work while cycle 15 finishes;
it does not change that cycle's sample, decision or frozen implementation.

## Motivation and verified provenance

The [official AppWorld README](https://github.com/StonyBrookNLP/appworld#-downloading-our-experiment-outputs)
states that its output release includes training agent trajectories. The download
module in our pinned AppWorld 0.1.3.post1 image points to the public URL
`https://s3.us-west-2.amazonaws.com/appworld.dev/experiment-outputs-0.1.0.bundle`.
A HEAD request reports 83,466,311 bytes, last modified 2024-07-27. This historical
archive is not assumed to share today's experiment names or native outcome scores.

A competent external source policy might supply missing donor programs without
more paid sampling. This is a hypothesis, not an observed source-quality result.
An offline corpus must be shared by every eventual memory/control arm. External
source-policy/model/demonstration differences and unknown historical acquisition
costs cannot disappear from later comparison accounting.

## Exact permitted operation now

Download the encrypted release once to a new research-artifact directory, with
a 100 MB maximum, exclusive file creation, content hash, timestamp and response
metadata. Do not overwrite an existing or partial download. In the unchanged
network-isolated pinned native image, decrypt with the package's public bundle
utility and **list ZIP member metadata only**. Do not call `extractall`, read a
member body, execute a trajectory, parse evaluator labels or open any task text.

Report experiment-directory names, sizes/counts and filenames for the eight
already allocated build tasks in directories labelled train. Those task IDs are
`27e1026_1`, `b7a9ee9_1`, `60d0b5b_1`, `aa8502b_1`, `ce359b5_1`, `cf6abd2_1`,
`287e338_1`, `3c13f5a_1`. Reserved dev/audit/evaluation tasks and the excluded
oracle scenario are not candidates. Merely holding an encrypted/compressed
archive is not permission to inspect its nonselected payloads.

The question is only whether a train-labelled, historically released baseline
run has archived program/log entries for these fixed build IDs. A directory name
is not verified source identity, success, replay eligibility or freedom from
demonstration leakage. Preserve absence and format mismatches, with no task/model
selection based on outcomes. Zero paid calls, zero native task executions.

## Gate and subsequent work

**KEEP** this source route for further inspection only if the archive integrity
and listing succeed and a fixed train-run candidate covers the existing build
IDs. Otherwise **REVISE** availability/format assumptions; do not use test outputs.
No outcome-contrast or learned-method claim follows from this metadata gate.

Before opening selected file bodies, freeze the exact experiment, selected task
set, public-program/observation file allowlist, parser and exclusions in a separate
protocol. Audit the original agent's source-information path, then replay all
selected programs in isolated fresh native worlds with the existing fail-closed
policy. A released success flag alone must never serve as our replay outcome.
Unsupported source code, changed API behavior, missing seeds, manually supplied
examples and task-specific source logic must be disclosed, not silently repaired.

The whole original archive, native-version binding, listing code and manifest
will be retained. No changes to vendor code, original documents, evaluator,
reserved partitions or the active paid source collector are needed.
