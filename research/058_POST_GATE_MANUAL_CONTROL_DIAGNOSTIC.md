# Post-gate manual coverage control: diagnostic specification

Recorded 2026-09-16 after the completed strict Cycle-22 decision, before running
the new manual control. This is a bounded follow-up on the same fourteen known
development records, not a resumed Cycle-23 proposal run or a held-out experiment.
The source programs AND their outcomes have already been inspected. Human rules
are deliberately informed by that inspection and the public API/task semantics.
No generalization, independent discovery or learned-method claim is permitted.

## Question and competing explanation

Can explicit human-written collection-coverage checks identify the four native
failures left clear by B? If so, these failures are not evidence that a learned
contract is needed. Also check whether a task-successful action still attracts
a defensible procedural warning; do not confuse warnings with native truth.

The manual control uses B's saved name warnings plus public-task-scoped checks:

- An explicitly emptied collection consumed without a producer.
- A single call to the required, documented paginated producer.
- Recognized pagination patterns must connect the actual API response to the
  consumed collector, advance the actual page index, and terminate on an empty
  response (with an optional short-page early exit). A loop node alone is not
  sufficient. Other shapes are unknown, not silently certified.
- For the all-classical-artists task, retain the actual genre literal and warn
  when a first-artist-only selection feeds a follow call.

These are bounded warning/pattern rules, NOT a sound or complete Python verifier.
Recognizing a pagination idiom does not prove API stability, response types,
short-page terminal semantics, every downstream effect, or universal correctness.
Unknown shapes abstain. Domain knowledge belongs explicitly to the manual arm.

literals, public task instruction, public API documentation and the complete
public name-presence envelope. Reject unsupported credential expressions. This
is a bounded direct-literal redactor, not a general secret detector. Export no
source IDs, native labels, runtime error outputs, hidden values or evaluator
contents into the decision function. The public API catalog is shared across
the fourteen known-build views; it is not a held-out catalog-selection policy.

The manual function takes only that public view. Reuse B's already recorded
warnings; do not rerun Ruff, the native benchmark, the sandbox or model generation.
Report pagination and consumer findings separately, full fourteen-row decisions,
native-outcome association, added warnings on native failures/successes, and
abstentions. Native outcomes are attached only after each decision. These are
classification associations, NOT causal task flips or recovery benefits.

Test alpha-renaming, missing advancement, disconnected accumulation, unsupported

Do not promote a learned formulation from any result here. If the manual
