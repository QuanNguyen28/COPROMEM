# Cycle 17A: preregistered all-boundary source coverage diagnostic

Registered 2026-09-16 after cycle 16's complete outcome/final-action audits and
**before running the broader all-boundary screen**. This is an explicitly
exploratory build-corpus revision, not a prospective held-out efficacy test.
No model calls or native execution are authorized by this screen protocol.

## Falsifiable question

Does applying the same `common-binding-backward-block-v1` operator to all recorded
action pairs recover syntactic repair coverage for an independent build task
that had none under final-action alignment? The mechanism is moving alignment to
where procedures are actually executed, not adding a new domain rule. The strongest
alternatives are accidental name overlap, unavailable donor state, unsupported
syntax, API side effects, and a successful task's irrelevant/noncausal action.

Primary metric: number of build task IDs other than the old aa8502b_1 task with
at least one supported candidate at a provenance-valid target boundary. That old
exclusion only prevents recounting already known coverage; its entire search is
still run and reported. **KEEP this alignment expansion for subsequent effect
tests** if the metric is at least one and all registered pairs are retained with
integrity checks; otherwise **REVISE**. This gate does not assert effect, new-rule
independent support, scope, admission, retrieval, transfer, or novelty.

## Fixed sample and exhaustive search

Use exactly the audited 32 source records in cycle 16's all-source screen, on the
same eight build task IDs. Keep the old unsupported source excluded. Use every
same-task pair of an eligible failed fixed-team episode and an eligible successful
source (fixed-team or archived program). No endpoint from an archive is falsely
labeled as a planner/executor handoff. Preserve a registry row for every task,
source contrast, target action and donor action; do not filter by native pass-count
details, source length or the desired outcome.

For each contrast, enumerate target action index then donor action index, both
zero-based ascending. Target boundary must bind the original step, public handoff,
planner generation, exact saved prefix, supported full state and incomplete
completion flag. Record and exclude unsupported/already-completed targets without
searching for an alternative checkpoint. Failed target actions remain valid
repair targets. Donor action errors are retained but not used as positive action
evidence; the whole episode's success does not establish their correctness.

Otherwise call the **unchanged single-program AST operator** on the two exact
action strings. Retain every lexical-scope rejection, identical block, duplicate
AST reason, proposal and null. No concatenating actions, identifier renaming,
task-specific constants/rules, LLM interpretation or manual edit is allowed in
17A. Donor actions remain proposals only: namespace availability and semantic
effect are not established by this syntactic screen.

Bind proposals to source digests, both action indices, exact code, target planner
and state digest, donor action provenance, and operator/source implementation
digests. Record per-task/per-contrast denominators, candidate counts, error/syntax/
boundary exclusions and duplicate proposals across action pairs. Raw support
counts are not independent task counts. No candidate may be admitted here.

## Before any later effect experiment

Freeze candidate selection without using intervention outcomes. A separate
protocol must specify budget, deterministic selection, exact target checkpoint,
unchanged original future-action continuation or a fairly budgeted regeneration
policy, factual controls, prefix replay, scorer invariance and harmful-flip checks.
The all-boundary screen alone never licenses treating an untested edit as memory.

Shared-source fairness, the archive's human-authored demonstration/unknown historical
costs, strong static/text/equal-compute controls, group-disjoint validation and the
two-independent-task admission threshold remain unchanged. Source acquisition and
local repair search are not a final method comparison.
