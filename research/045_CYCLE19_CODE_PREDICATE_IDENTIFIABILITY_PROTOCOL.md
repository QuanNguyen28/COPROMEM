# Cycle 19: effect-backed public-code predicate identifiability

Registered 2026-09-16 after the complete cycle-18B audit and before implementing
or running the following feature miner. This is an explicitly **post-outcome
development diagnostic** on already inspected build evidence, not a prospective
held-out efficacy test. Branch/HEAD and earlier frozen evidence are unchanged.
Zero new model calls, native executions, external API USD or admissions.

## Question, hypothesis and falsifier

Can an explicitly generic, restricted executable code-predicate language derive
a separator from the two known repaired source pairs that remains consistent
with the other already recorded local effects? This tests a minimal proposal
representation before building runtime recovery around it. It does not equate
final-task outcome with a uniquely defective boundary artifact.

The strongest competing explanation is syntactic overfitting: many properties
change together in successful patches, but none identifies semantic correctness
or intent. Additional computation, stale continuation, external state and
unrelated downstream errors can determine the final label. A code-only check
cannot generally distinguish two identical code strings used in different states.

The primary diagnostic is the number of single-clause predicates satisfying both
training contrasts and all recorded eligible diagnostic labels below. KEEP this
bounded language for further counterexample/scope testing only if at least one
exists. Otherwise REVISE it. An empty or ambiguous version space is a first-class
finding, not a reason to add domain-specific features after seeing the screen.

## Frozen generic language and exhaustive learning rule

Parse each complete submitted action without executing it. Enumerate counts of:

1. Every Python AST node type present, including operator/context nodes.
2. Every direct `(parent node type, AST field name, child node type)` edge.

Do not include identifier spellings, attribute/API names, string/numeric literal
values, source positions or task metadata. No selected list of loop, collection,
pagination, authentication or benchmark-specific features is permitted. Count
all nodes/edges uniformly, including nested code; this deliberately remains a
syntactic language, not a sound control/dataflow or runtime verifier.

For each feature occurring in any training program, enumerate each distinct
observed count as a threshold and both `count >= threshold` and
`count <= threshold`. A clause predicts acceptable code when true. Retain every
clause that accepts both repaired training programs and rejects both original
programs. Record the full enumeration, rejection reasons and accepted version
space. No semantic tie-breaking, manual threshold adjustment, conjunction search,
feature expansion or selection using diagnostic labels is allowed.

Run leave-one-source-pair-out construction in each direction as a descriptive
representation check. Report all candidates and their predictions on the other
already known pair; do not call this reserved-test transfer. Apply every retained
two-pair clause unchanged to every diagnostic cell. Also report identical-feature
vector and identical normalized-AST groups with conflicting labels. These expose
representation/label ambiguity but do not prove contract learning impossible.

Represent clauses as validated JSON with an allowlisted comparator and a positive
feature description, interpreted directly without `eval`, `exec`, importing or
running source code. Malformed syntax/schema returns an explicit error/abstention,
not acceptance. Serialization/reload must preserve predictions. No predicate is
installed in the main runtime, allowed to trigger recovery or admitted to a bank.

## Metrics, integrity and decision

Report training enumeration/consistent counts; distinct equivalent prediction
groups; every clause's confusion counts on all 48 cells and the subset without
an exact training-origin/program overlap; conflicting-label groups; leave-pair-
out counts; errors/exclusions; model/native/USD zeros. The primary count requires
no classification error on every eligible diagnostic cell. Do not redefine it
after observation; false acceptance means disagreement with native final outcome,
not a proven verifier false positive against boundary-level ground truth.

Snapshot this protocol, new miner/runner/tests and their imported support files
before the real screen. Preserve original source snapshots. Full regeneration
must check frozen code, source evidence identities, exact directory inventories,
all feature rows, clause serialization, labels, metrics and the decision. Unit
tests must cover arbitrary names/APIs, literal and spelling invariance, every
node/edge class treatment, contradictory examples, reversed labels, malformed
inputs, no source execution, complete enumeration, comparison boundaries and
source-to-public-example integrity. Never write hidden state into miner inputs.

Even KEEP would mean only that this limited separator language survives a known
development registry. It cannot establish semantic sufficiency, learned scope,
